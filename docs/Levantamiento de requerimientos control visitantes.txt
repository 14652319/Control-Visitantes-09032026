```
assets/
├── images/
│   ├── logo.png          (Logo de la empresa - PNG transparente)
```

### Logo
- **Formato:** PNG con fondo transparente
- **Tamaño recomendado:** 200x200px mínimo
- **Ubicación:** `assets/images/logo.png`

### Patrón de Fondo
- **Formato:** SVG
- **Descripción:** Patrón sutil repetible (simula textura de caña)
- **Tamaño:** 400x400px
- **Opacidad:** Muy sutil (no debe distraer del contenido)
- **Ubicación:** `assets/images/cana-pattern.svg`

**Nota:** Si no tienes el patrón SVG, puedes usar un color sólido:
```html
<body class="bg-gray-50">
    <!-- Sin imagen de fondo -->
</body>
```

20. VALIDACIONES DE CONTRASEÑA
================================================================================

✅ IMPLEMENTADAS: Requisitos de contraseña

Requisitos al crear/cambiar contraseña:
- Longitud mínima: 8 caracteres
- Al menos 1 mayúscula
- Al menos 1 minúscula
- Al menos 1 número
- Al menos 1 caracter especial (!@#$%^&*()_+-=[]{}|;:,.<>?)

Validación en backend (Python):
def validar_password(password):
    if len(password) < 8:
        return False, "Mínimo 8 caracteres"
    if not re.search("[a-z]", password):
        return False, "Debe contener minúsculas"
    if not re.search("[A-Z]", password):
        return False, "Debe contener mayúsculas"
    if not re.search("[0-9]", password):
        return False, "Debe contener números"
    if not re.search("[!@#$%^&*()_+-=[\]{}|;:,.<>?]", password):
        return False, "Debe contener caracteres especiales"
    return True, "Válida"

Hashing:
- Biblioteca: bcrypt
- Rounds: 12
- Salt automático

Almacenamiento:
- Campo: password_hash (255 caracteres)
- NUNCA se almacena contraseña en texto plano
- NUNCA se retorna en respuestas JSON

33. SISTEMA AVANZADO DE BÚSQUEDA Y FILTROS EN LISTADO
================================================================================

✅ IMPLEMENTADO: Filtros y paginación en listado de visitantes

A) BÚSQUEDA POR IDENTIFICACIÓN:
   - Campo de búsqueda con debounce de 500ms
   - Búsqueda parcial (ILIKE) en:
     * Número de identificación
     * Primer nombre
     * Primer apellido
   - Case-insensitive
   - Actualización automática al escribir
   
   Ejemplo: Al escribir "123" encuentra:
   - Identificación: 12345678
   - Nombre: Juan 1234
   - Apellido: González123

B) FILTRO DE RANGO DE FECHAS:
   Campos:
   - Fecha Desde (fecha_desde)
   - Fecha Hasta (fecha_hasta)
   
   Comportamiento:
   - DEFAULT: Ambas fechas en DÍA ACTUAL
   - Permite seleccionar cualquier rango
   - Búsquedas históricas ilimitadas
   - Validación: fecha_desde <= fecha_hasta
   - Formato: YYYY-MM-DD (input type="date")
   
   Uso típico:
   - Por defecto: Ver visitantes de hoy
   - Histórico: Cambiar fechas para auditorías
   - Rango: Semana pasada, mes anterior, etc.

C) FILTRO POR ESTADO:
   Opciones:
   - "Todos los visitantes" (sin filtro)
   - "Solo en instalaciones" (estado = EN_INSTALACIONES)
   - "Solo los que salieron" (estado = SALIO)
   
   Permite:
   - Ver quién está actualmente en instalaciones
   - Ver histórico completo de ingresos/egresos
   - Auditorías específicas por estado

D) PAGINACIÓN:
   Características:
   - 100 registros por página (configurable)
   - Navegación con botones:
     * "Anterior" (deshabilitado en página 1)
     * Números de página (máximo 5 botones visibles)
     * "Siguiente" (deshabilitado en última página)
   - Información: "Página X de Y"
   - Total de registros: "Mostrando: X visitantes"
   - Scroll automático al inicio al cambiar página
   
   Comportamiento inteligente:
   - Si hay ≤5 páginas: Muestra todos los números
   - Si hay >5 páginas: Muestra solo 5 números alrededor de página actual
   - Primera y última página siempre accesibles

E) BOTÓN "LIMPIAR FILTROS":
   Acción:
   - Restablece búsqueda a vacío
   - Restablece fechas al día actual
   - Restablece estado a "todos"
   - Regresa a página 1
   - Recarga lista automáticamente
   
   Ubicación: Al lado de los controles de filtro

F) CONTADOR TOTAL:
   - Badge en pestaña: "VISITANTES DE HOY (X)"
   - Muestra total de registros encontrados
   - Se actualiza con cada filtro
   - Tooltip informativo

G) IMPLEMENTACIÓN BACKEND:
   Endpoint: GET /api/visitantes/listar
   
   Parámetros:
   - fecha_desde: string (YYYY-MM-DD)
   - fecha_hasta: string (YYYY-MM-DD)
   - busqueda: string (opcional)
   - estado: string (EN_INSTALACIONES | SALIO | null)
   - pagina: integer (default: 1)
   - por_pagina: integer (default: 100)
   
   Respuesta JSON:
   {
     "success": true,
     "total": 523,
     "pagina": 1,
     "por_pagina": 100,
     "total_paginas": 6,
     "visitas": [...]
   }
   
   Query SQL optimizada:
   ```python
   query = LogVisitante.query.filter(
       LogVisitante.sede_id == sede_id,
       LogVisitante.fecha_ingreso.between(fecha_desde, fecha_hasta)
   )
   
   if busqueda:
       query = query.filter(db.or_(
           LogVisitante.num_identificacion.ilike(f'%{busqueda}%'),
           LogVisitante.primer_nombre.ilike(f'%{busqueda}%'),
           LogVisitante.primer_apellido.ilike(f'%{busqueda}%')
       ))
   
   if estado:
       query = query.filter(LogVisitante.estado_visita == estado)
   
   pagination = query.order_by(
       LogVisitante.fecha_ingreso.desc()
   ).paginate(page=pagina, per_page=por_pagina, error_out=False)
   ```

TABLA: autorizaciones_sst
═══════════════════════════════════════════════════════════════════════════════
DESCRIPCIÓN: Autorizaciones de SST para ingreso de contratistas (la principal)

ESTRUCTURA:
    id                      SERIAL PRIMARY KEY
    numero_autorizacion     VARCHAR(50) UNIQUE NOT NULL    # Consecutivo: "SST-2026-0001"
    empresa_id              INTEGER NOT NULL REFERENCES empresas_contratistas(id)
    planilla_ss_id          INTEGER NOT NULL REFERENCES planillas_seguridad_social(id)
    
    -- Vigencia BASADA EN LA PLANILLA:
    fecha_autorizacion      DATE NOT NULL DEFAULT CURRENT_DATE
    hora_autorizacion       TIME NOT NULL DEFAULT CURRENT_TIME
    vigencia_inicio         DATE NOT NULL                  # Copia de planilla.periodo_salud_inicio
    vigencia_fin            DATE NOT NULL                  # Copia de planilla.vigencia_hasta
    
    -- Sede:
    sede_id                 INTEGER NOT NULL REFERENCES sedes(id)
    
    -- Estado del proceso:
    estado                  VARCHAR(50) NOT NULL DEFAULT 'BORRADOR'
    # 'BORRADOR'  - En proceso de registro (puede editar)
    # 'REVISION'  - Completo, pendiente aprobación
    # 'APROBADA'  - Aprobada por admin_sst (genera PDF)
    # 'RECHAZADA' - Rechazada (con motivo)
    # 'VENCIDA'   - Pasó vigencia_fin (auto-marcado)
    # 'ANULADA'   - Anulada manualmente
    
    motivo_rechazo          TEXT                           # Si estado='RECHAZADA'
    
    -- Responsable SST que firma:
    responsable_sst_id      INTEGER REFERENCES usuarios(id)  # admin_sst
    nombre_responsable      VARCHAR(200)                   # Nombre completo para PDF
    cargo_responsable       VARCHAR(100)                   # Ej: "Seguridad y Salud en el Trabajo"
    
    -- Archivo PDF generado:
    ruta_pdf_generado       VARCHAR(500)                   # uploads/autorizaciones_sst/{año}/{consecutivo}.pdf
    
    -- Auditoría:
    fecha_creacion          TIMESTAMP DEFAULT NOW()
    fecha_modificacion      TIMESTAMP DEFAULT NOW()
    fecha_aprobacion        TIMESTAMP                      # Cuándo se aprobó
    usuario_registro_id     INTEGER NOT NULL REFERENCES usuarios(id)
    usuario_aprobacion_id   INTEGER REFERENCES usuarios(id)
    
    CREATE INDEX idx_autoriz_sst_numero ON autorizaciones_sst(numero_autorizacion);
    CREATE INDEX idx_autoriz_sst_empresa ON autorizaciones_sst(empresa_id);
    CREATE INDEX idx_autoriz_sst_estado ON autorizaciones_sst(estado);
    CREATE INDEX idx_autoriz_sst_vigencia ON autorizaciones_sst(vigencia_fin);

VALIDACIONES:
    ✅ numero_autorizacion único (formato: SST-{AÑO}-{CONSECUTIVO:04d})
    ✅ Solo estado='BORRADOR' permite edición
    ✅ Transiciones válidas:
       BORRADOR → REVISION → APROBADA | RECHAZADA
       APROBADA → VENCIDA (auto, si vigencia_fin < hoy)
       APROBADA → ANULADA (manual, solo master)
    ✅ PDF se genera SOLO cuando estado='APROBADA'

│                        VALIDACIONES CRÍTICAS                                │
└─────────────────────────────────────────────────────────────────────────────┘

1. VIGENCIA DE PLANILLA:
   ✅ vigencia_hasta = fecha_pago + 30 días
   ✅ Calculado automáticamente por el backend
   ✅ NO permitir ingreso si vigencia_hasta < hoy

2. VIGENCIA DE CERTIFICADOS:
   ✅ Certificado vigente = fecha_vencimiento >= vigencia_fin de la autorización
   ✅ Ejemplo: Si autorización vigente hasta 12/04/2026
      → Certificado de alturas debe vencer MÍNIMO el 12/04/2026 o después

3. CONSECUTIVOS DE AUTORIZACIÓN:
   ✅ Formato: SST-{AÑO}-{CONSECUTIVO:04d}
   ✅ Ejemplo: SST-2026-0001, SST-2026-0002, ...
   ✅ Se genera AL APROBAR (no al crear en BORRADOR)
   ✅ Reinicia cada año

4. ESTADOS DE AUTORIZACIÓN:
   ✅ BORRADOR → REVISION → APROBADA
   ✅ APROBADA → VENCIDA (automático)
   ✅ APROBADA → ANULADA (manual, solo master)
   ✅ Transiciones bloqueadas:
      ❌ No se puede aprobar si hay certificados vencidos
      ❌ No se puede aprobar si planilla está vencida
      ❌ No se puede editar si estado != BORRADOR

5. PERMISOS POR SEDE:
   ✅ admin_sst solo ve autorizaciones de su sede
   ✅ operador_seguridad solo registra ingresos de su sede
   ✅ usuario_master ve TODAS las sedes

6. REGISTROS DE INGRESO/SALIDA:
   ✅ No se puede registrar ingreso si autorización NO está en estado APROBADA
   ✅ No se puede registrar ingreso si autorización está VENCIDA
   ✅ No se puede registrar ingreso duplicado (empleado ya EN_INSTALACIONES)
   ✅ No se puede registrar salida si no hay ingreso previo

7. APORTES DE SEGURIDAD SOCIAL:
   ✅ Persona jurídica: DEBE aportar salud, pensión, ARL
   ✅ Persona natural: Puede NO aportar pensión (si es pensionado)
   ✅ Si NO aporta, observación es obligatoria

FUNCIÓN GENERADORA (backend/app/services/pdf_service.py):
from weasyprint import HTML
from flask import render_template
import os

def generar_pdf_autorizacion_sst(autorizacion_id):
    """
    Genera PDF de autorización SST
    """
    # Obtener datos
    autorizacion = AutorizacionSST.query.get(autorizacion_id)
    empresa = autorizacion.empresa
    planilla = autorizacion.planilla_ss
    empleados_data = []
    
    for ea in autorizacion.empleados_autorizacion:
        emp = ea.empleado
        certs = []
        if ea.autorizado_alturas:
            certs.append("Alturas")
        if ea.autorizado_electrico:
            certs.append("Eléctrico")
        
        empleados_data.append({
            "nombre": emp.nombre_completo(),
            "cedula": emp.num_identificacion,
            "certificaciones": ", ".join(certs) if certs else "N/A"
        })
    
    # Renderizar plantilla
    html_content = render_template(
        'pdf_autorizacion_sst.html',
        num_autorizacion=autorizacion.numero_autorizacion,
        fecha=autorizacion.fecha_autorizacion.strftime('%d/%m/%Y'),
        hora=autorizacion.hora_autorizacion.strftime('%H:%M'),
        empresa_nit=empresa.nit,
        empresa_razon_social=empresa.razon_social,
        planilla_numero=planilla.numero_planilla,
        planilla_operador=planilla.operador_aportes.razon_social,
        vigencia_inicio=autorizacion.vigencia_inicio.strftime('%d/%m/%Y'),
        vigencia_fin=autorizacion.vigencia_fin.strftime('%d/%m/%Y'),
        empleados=empleados_data,
        restricciones=[],  # Extraer de empleados
        sede_nombre=autorizacion.sede.nombre,
        responsable_nombre=autorizacion.nombre_responsable,
        responsable_cargo=autorizacion.cargo_responsable
    )
    
    # Generar PDF
    año = autorizacion.fecha_autorizacion.year
    carpeta = f"uploads/autorizaciones_sst/{año}"
    os.makedirs(carpeta, exist_ok=True)
    
    nombre_pdf = f"{autorizacion.numero_autorizacion}.pdf"
    ruta_completa = os.path.join(carpeta, nombre_pdf)
    
    HTML(string=html_content).write_pdf(ruta_completa)
    
    # Actualizar registro
    autorizacion.ruta_pdf_generado = ruta_completa
    db.session.commit()
    
    return ruta_completa
