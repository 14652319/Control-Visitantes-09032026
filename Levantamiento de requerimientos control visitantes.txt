```
assets/
├── images/
│   ├── logo.png          (Logo de la empresa - PNG transparente)
```

### Logo
- **Formato:** PNG con fondo transparente
- **Tamaño recomendado:** 200x200px mínimo
- **Ubicación:** `assets/images/logo.png`

### Patrón de Fondo
- **Formato:** SVG
- **Descripción:** Patrón sutil repetible (simula textura de caña)
- **Tamaño:** 400x400px
- **Opacidad:** Muy sutil (no debe distraer del contenido)
- **Ubicación:** `assets/images/cana-pattern.svg`

**Nota:** Si no tienes el patrón SVG, puedes usar un color sólido:
```html
<body class="bg-gray-50">
    <!-- Sin imagen de fondo -->
</body>
```

20. VALIDACIONES DE CONTRASEÑA
================================================================================

✅ IMPLEMENTADAS: Requisitos de contraseña

Requisitos al crear/cambiar contraseña:
- Longitud mínima: 8 caracteres
- Al menos 1 mayúscula
- Al menos 1 minúscula
- Al menos 1 número
- Al menos 1 caracter especial (!@#$%^&*()_+-=[]{}|;:,.<>?)

Validación en backend (Python):
def validar_password(password):
    if len(password) < 8:
        return False, "Mínimo 8 caracteres"
    if not re.search("[a-z]", password):
        return False, "Debe contener minúsculas"
    if not re.search("[A-Z]", password):
        return False, "Debe contener mayúsculas"
    if not re.search("[0-9]", password):
        return False, "Debe contener números"
    if not re.search("[!@#$%^&*()_+-=[\]{}|;:,.<>?]", password):
        return False, "Debe contener caracteres especiales"
    return True, "Válida"

Hashing:
- Biblioteca: bcrypt
- Rounds: 12
- Salt automático

Almacenamiento:
- Campo: password_hash (255 caracteres)
- NUNCA se almacena contraseña en texto plano
- NUNCA se retorna en respuestas JSON

33. SISTEMA AVANZADO DE BÚSQUEDA Y FILTROS EN LISTADO
================================================================================

✅ IMPLEMENTADO: Filtros y paginación en listado de visitantes

A) BÚSQUEDA POR IDENTIFICACIÓN:
   - Campo de búsqueda con debounce de 500ms
   - Búsqueda parcial (ILIKE) en:
     * Número de identificación
     * Primer nombre
     * Primer apellido
   - Case-insensitive
   - Actualización automática al escribir
   
   Ejemplo: Al escribir "123" encuentra:
   - Identificación: 12345678
   - Nombre: Juan 1234
   - Apellido: González123

B) FILTRO DE RANGO DE FECHAS:
   Campos:
   - Fecha Desde (fecha_desde)
   - Fecha Hasta (fecha_hasta)
   
   Comportamiento:
   - DEFAULT: Ambas fechas en DÍA ACTUAL
   - Permite seleccionar cualquier rango
   - Búsquedas históricas ilimitadas
   - Validación: fecha_desde <= fecha_hasta
   - Formato: YYYY-MM-DD (input type="date")
   
   Uso típico:
   - Por defecto: Ver visitantes de hoy
   - Histórico: Cambiar fechas para auditorías
   - Rango: Semana pasada, mes anterior, etc.

C) FILTRO POR ESTADO:
   Opciones:
   - "Todos los visitantes" (sin filtro)
   - "Solo en instalaciones" (estado = EN_INSTALACIONES)
   - "Solo los que salieron" (estado = SALIO)
   
   Permite:
   - Ver quién está actualmente en instalaciones
   - Ver histórico completo de ingresos/egresos
   - Auditorías específicas por estado

D) PAGINACIÓN:
   Características:
   - 100 registros por página (configurable)
   - Navegación con botones:
     * "Anterior" (deshabilitado en página 1)
     * Números de página (máximo 5 botones visibles)
     * "Siguiente" (deshabilitado en última página)
   - Información: "Página X de Y"
   - Total de registros: "Mostrando: X visitantes"
   - Scroll automático al inicio al cambiar página
   
   Comportamiento inteligente:
   - Si hay ≤5 páginas: Muestra todos los números
   - Si hay >5 páginas: Muestra solo 5 números alrededor de página actual
   - Primera y última página siempre accesibles

E) BOTÓN "LIMPIAR FILTROS":
   Acción:
   - Restablece búsqueda a vacío
   - Restablece fechas al día actual
   - Restablece estado a "todos"
   - Regresa a página 1
   - Recarga lista automáticamente
   
   Ubicación: Al lado de los controles de filtro

F) CONTADOR TOTAL:
   - Badge en pestaña: "VISITANTES DE HOY (X)"
   - Muestra total de registros encontrados
   - Se actualiza con cada filtro
   - Tooltip informativo

G) IMPLEMENTACIÓN BACKEND:
   Endpoint: GET /api/visitantes/listar
   
   Parámetros:
   - fecha_desde: string (YYYY-MM-DD)
   - fecha_hasta: string (YYYY-MM-DD)
   - busqueda: string (opcional)
   - estado: string (EN_INSTALACIONES | SALIO | null)
   - pagina: integer (default: 1)
   - por_pagina: integer (default: 100)
   
   Respuesta JSON:
   {
     "success": true,
     "total": 523,
     "pagina": 1,
     "por_pagina": 100,
     "total_paginas": 6,
     "visitas": [...]
   }
   
   Query SQL optimizada:
   ```python
   query = LogVisitante.query.filter(
       LogVisitante.sede_id == sede_id,
       LogVisitante.fecha_ingreso.between(fecha_desde, fecha_hasta)
   )
   
   if busqueda:
       query = query.filter(db.or_(
           LogVisitante.num_identificacion.ilike(f'%{busqueda}%'),
           LogVisitante.primer_nombre.ilike(f'%{busqueda}%'),
           LogVisitante.primer_apellido.ilike(f'%{busqueda}%')
       ))
   
   if estado:
       query = query.filter(LogVisitante.estado_visita == estado)
   
   pagination = query.order_by(
       LogVisitante.fecha_ingreso.desc()
   ).paginate(page=pagina, per_page=por_pagina, error_out=False)
   ```
